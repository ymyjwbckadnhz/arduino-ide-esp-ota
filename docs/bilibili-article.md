# Arduino IDE 2 的 OTA 死活连不上？我写了个插件，直接填 IP 就能传

> 一个专门解决 "Arduino IDE 2 找不到网络端口 / OTA 上传失败" 的开源插件。
> 手动指定 IP，绕过 mDNS 发现，单播直连。支持 ESP32 全系和 ESP8266。

---

## 先说痛点

用 Arduino IDE 2 给 ESP32 / ESP8266 做 OTA 无线升级，很多人卡在同一步：

**IDE 的网络端口列表里，根本看不到你的板子。**

或者看到了，点上传却报这个错：

```
espota.exe: error: argument -p/--port: invalid int value: '{upload.port.properties.port}'
```

这行报错看起来很怪——**IP 明明获取到了（`-i 10.0.0.27` 是对的），但端口号是个没被替换的模板变量**。

原因在于：Arduino IDE 2 的 OTA 上传依赖 **mDNS 发现**。它通过 `_arduino._tcp` 服务拿到设备的 IP 和端口，再拼出 espota 命令。一旦 mDNS 这条路不通，端口号就是空的，命令直接报错。

而 mDNS 在很多真实网络环境下就是不通的：

- **mDNS 用的是 `224.0.0.251` 组播，TTL = 1**，设计上就不出本地链路。设备和你不在同一个广播域，ping 得通，mDNS 永远不通
- 家里是 **FTTR（主光猫 + 从光猫）**，设备接在另一台光猫上
- 交换机 / AP 开了 **IGMP Snooping**，未订阅的组播被直接丢弃
- 公司、学校、酒店网络禁组播

更尴尬的是：**你明明知道设备的 IP，却没有地方填。**

IDE 只能从"发现到的端口"里选，没有"手动输入 IP"这个选项。

---

## 解决办法

既然 IDE 不让填 IP，那就换个思路——**绕过 IDE 的端口发现，自己做上传入口**。

Arduino IDE 2 是 Theia（Electron）架构，**支持装 VS Code 扩展**。官方还提供了 `vscode-arduino-api`，让插件能读到当前 sketch、开发板、编译产物。

所以我写了个插件 **ESP OTA Uploader**：

> 命令面板 / 状态栏点一下 → 输入 IP → 输密码 → 传。

不依赖 mDNS，不依赖网络发现，**走单播直连**，跨几层路由器都能传。

GitHub：https://github.com/ymyjwbckadnhz/arduino-ide-esp-ota

---

## 功能

| 能力 | 说明 |
|---|---|
| 手动指定 IP | 这就是核心。想传哪台传哪台，不受网络拓扑限制 |
| **自动识别芯片** | 读 sketch 源码判断 ESP32 还是 ESP8266，自动选对端口和工具 |
| 自动选端口 | ESP32 → 3232，ESP8266 → 8266；识别不到就两个都试 |
| 记住 IP 和密码 | 之后每次上传就**两次回车** |
| 三个入口 | 状态栏按钮 / 命令面板 / `Ctrl+Alt+U` |
| 自动重试 | 设备重启期间会自动等 5 秒重试，最多 2 次 |
| 进度反馈 | 状态栏实时百分比 + 右上角进度通知 |

## 安装

插件没有上架任何商店，**手动放文件**即可：

**1. 下载 `.vsix`**

去仓库 Releases 页面下载 `esp-ota-uploader-x.x.x.vsix`。

**2. 放到插件目录**

```
Windows:      C:\Users\<你的用户名>\.arduinoIDE\plugins\
macOS/Linux:  ~/.arduinoIDE/plugins/
```

目录不存在就自己新建一个。

**3. 重启 Arduino IDE**

重启后，状态栏右下角会出现一个 ☁ **OTA** 按钮。

> 如果你的 IDE 版本不显示状态栏按钮，用命令面板也一样：
> `Ctrl+Shift+P` → 输入 `ESP OTA`

---

## 使用

**① 先编译一次**

`Ctrl+R` 或点验证按钮。插件读的是 IDE 的编译产物，只负责上传，不负责编译。

**② 触发上传**

- 点状态栏的 ☁ **OTA**
- 或 `Ctrl+Alt+U`
- 或 `Ctrl+Shift+P` → `ESP OTA: Upload to IP`

**③ 两步输入**

```
┌─ OTA 目标 IP（1/2）─────────────┐
│ 192.168.1.50                    │  ← 预填上次的，回车沿用
└─────────────────────────────────┘
┌─ OTA 密码（2/2）───────────────┐
│ ●●●●●●●●                        │  ← 预填已保存的，回车沿用
│ 已保存密码，直接回车沿用；       │
│ 重新输入可覆盖；输入 - 清除       │
└─────────────────────────────────┘
```

之后每次都是**两次回车**搞定。

## 原理：为什么它必须是这个做法

这里有几个坑，值得单独说，因为**它们解释了为什么"随便找个 OTA 工具"不行**。

### 坑 1：ESP32 和 ESP8266 用的是两套 espota

这是最隐蔽的一个。

Arduino 的 OTA 上传靠 `espota`。但：

- **ESP32 核心**自带 `espota.exe`（新协议，支持 PBKDF2 认证）
- **ESP8266 核心**自带 `espota.py`（老协议，MD5 认证）

**用 ESP32 那份去连 ESP8266，认证必然失败：**

```
Sending invitation to 10.0.0.27
Authenticating (MD5 protocol)...FAIL
Authentication Failed: No Answer to our Authentication
```

必须用设备所属**平台自带的那一份**。

而且两者的命令行参数还不一样：

| 参数 | ESP32 版 | ESP8266 版 |
|---|---|---|
| `-t` 超时 | 支持 | **不支持**（报 no such option）|
| `-r` | 传完重启 | 显示进度（**不是**重启）|

所以插件会先判断芯片，再决定用哪份工具、拼哪套参数。

### 坑 2：端口标签是 UDP，不是 TCP

ESP32 的 OTA 端口 **3232 是 UDP**。用 `telnet` 或者 TCP 探测会得到"拒绝连接"，看起来像服务没起来——其实一切正常。

ESP8266 是 **8266**。

猜错端口的代价很大：espota 会**重试 10 次**，每次 10 秒，**一共卡 100 秒**才报 `No response`。很多人就是卡在这里以为死机了。

所以插件优先按芯片识别端口，识别不到才两个都试，并且用 `-t 2` 把失败时间压到 20 秒以内。

### 坑 3：espota.py 有时候根本开不了本地端口

ESP8266 的 `espota.py` 会在本地随机开一个 TCP 端口，等设备反向连回来。但它有时候 bind 失败，**在跟设备通信之前就退出**：

```
[ERROR]: Listen Failed
```

修法是显式告诉它用哪个本机地址：

```bash
espota.py -i 10.0.0.27 -p 8266 -I 10.0.0.28 -f firmware.bin
```

插件会自动找与目标同网段的本机 IP 填进去。

### 坑 4：你以为是网络问题，其实是设备侧内存不够

这个坑最有教育意义。

调试过程中遇到一个诡异现象：**OTA 能成功一次，之后再也连不上。**

一开始怀疑网络、怀疑插件、怀疑密码。最后抓设备串口才看到：

```
<<<stack<<<
--------------- CUT HERE FOR EXCEPTION DECODER ---------------
Exception (29): excvaddr=0x00000008
```

**设备在收到 OTA 邀请包的瞬间崩溃重启了。** 所以 espota 永远等不到回应。

原因：ESP8266 只剩 3KB 空闲堆，而 OTA 在设备端要分配缓冲区。分配失败 → 空指针写入 → 崩溃。

这类问题**光看主机端日志永远查不出来**，只能在设备侧找。

## 实测数据

在真实硬件上跑过的数据：

| 场景 | 结果 |
|---|---|
| ESP32（96×128 HUB75 屏） | 连续多次成功 |
| ESP8266（240×240 LVGL 屏 + 网页服务） | 连续 4 次成功，22–25 秒/次 |
| 跨光猫（不在同一广播域） | 正常，因为走单播 |
| IDE 自带 OTA | 同一环境下完全不可用 |

固件约 680KB，WiFi 环境下 20 秒左右传完。

## 它不做什么

说清楚边界，避免误解：

**它不是"一键 OTA"**。你还是得先编译，再填 IP。

**它不能突破硬件限制**。如果设备内存紧张到跑不动 OTA，插件也没办法——那是固件要优化的事。

**它不替代串口烧录**。第一次烧录、或者固件彻底挂掉时，还是需要 USB。

## 什么时候你需要它

对号入座：

- ✅ IDE 的网络端口列表里看不到你的板子
- ✅ 看到端口但上传报 `{upload.port.properties.port}` 错误
- ✅ 板子和电脑不在同一个光猫 / 路由器下
- ✅ 公司或学校网络禁组播
- ✅ 你就是想手动指定 IP，不想依赖自动发现
- ✅ 你同时用 ESP32 和 ESP8266，受够了手动敲 espota 命令

如果 IDE 自带 OTA 在你机器上工作正常，那你可以不用装——**这插件是给"发现不了"的场景兜底的。**

## 写在最后

这个插件是踩了一堆坑之后逼出来的产物。

其中最有意思的是第 4 个坑：**"OTA 连不上"最后查到的是固件内存不够**，而不是网络或工具的问题。主机的日志只能看到"No Answer"，真相藏在设备串口里。

所以如果你用这个插件还是失败，建议先确认两件事：

1. 设备网页能打开吗？（能打开说明它活着且在 Wi-Fi 上）
2. 设备是不是刚重启完？等 10 秒再试
